# 局部核实与主线推进

2026-10-21。问题会话：`96331304181242e78b05ddc8637f1eca`，客户从产品介绍转向打游戏，再回答“3A”，客服交代适配待核实，客户回复“ok”。

## 根因

service-v4 的无进展分支消除了重复核实承诺，但规划器把整场客户决策缩成“当前产品是否适配3A”。只要 next_question=null 且有门店核实任务，程序就接受整体等待。原日志明确写“没有新的独立客户信息能推进该适配判断”；未评估具体游戏、实际负载、体验要求或与目标相关的选择约束。

一次简单的二元复核在真实重复回放中仍出现等待，故没有把单次模型给出好问题当作稳定修复。

## 修正

- 工作流版本为 5。对存在未完成核实、主规划无下一步问题且拟普通承接的客户轮次，增加一次有界 ProgressReview，记录在同一运行 trace 中。
- 复核分别评估 verification_scope（核实范围）、decision_criteria（客户判断标准）、decision_path（独立决策路径）。每条有状态与原因，useful 必须提供客户可回答的具体问题。不能只用“产品结论未知”否定其他路径。
- 输入以最初真实诉求、近期对话、已确认需求与实际问答为准，不把上次模型生成的“客户在等待”主题解释重新作为事实输入。
- 复核给出问题后仍由程序检查已知、人工锁定、已问、拒答与范围，再编译为独立 discover 任务。既有核实保持 waiting_staff，不伪装完成。
- 有已规划的独立下一步时，优先展示带有效问题的候选，action.reply 与展示排序一致；主规划和等待复核都遵守此规则，换一组保持此偏好。仍保留无追问表达，不强制每句都问问题。
- 话术只承接本轮新推进，不重复等待、跟进或通知承诺。即时联系承诺检查补充“同步/反馈/回访”等表达，防止同义绕过。
- 真正没有独立信息可了解时，仍允许无需回复的门店等待；不按空字段固定追问，不强制问预算或转推其他产品。
- 补充明确的选购接待服务目标：客户回答上一问后主动寻找有决策价值的下一步；不能仅因客户未主动提出体验标准就认定它不值得了解。明确只查某项事实或拒绝继续时仍尊重范围。
- 规划器输出 schema 移除 needs；个人信息由 ServiceCustomerUpdate 单独提取，程序将规范事实交给规划器。禁止规划器第二次写入个人事实，减少重复职责和输出结构。规划阶段单次上限由30秒调整为60秒，仍保留有界网络重试。

## 使用

本地服务更新后，刷新客服页并点击“更新分析”。有价值的独立步骤继续显示为回复建议；只有确实无独立路径时才显示整体等待。门店核实仍需实际处理并登记结果。
