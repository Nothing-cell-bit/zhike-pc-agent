# 提示词与调用设计

实际系统提示词为 [backend/prompts/marketing-system.txt](../../backend/prompts/marketing-system.txt)，由 `backend.ai.SYSTEM` 直接读取。修改该文件后需重启后端，不在说明书另复制一份可能过期的正文。

运行版本 `store-v4-ima`。每次请求由以下内容组成：

1. system：系统提示词全文 + 具体任务指令 + Pydantic JSON schema。
2. user：JSON 数据；包含脱敏 brief、已知场景、完整型号、实际 `source_type`（ima 或 local_zip）、平台 rule、带 ID / 原文 / 日期 / 版本 / 哈希的证据。ima 分支不混用本地例文；本地例文只作表达参考，不作事实依据。

## 生成任务

模型输出标题、导语、正文、行动引导、标签、场景主要问题、内容策略、事实与来源 ID、待确认项，以及 `conflicts`。同条件资料存在真实冲突时返回冲突说明与资料 ID，标题和正文留空；程序不保存成稿，界面显示人工确认问题。

购买阶段只使用操作者明确提供的值，未提供记为待确认。其余任务输入也保留原始 brief；模型对问题的概括与人工明确输入分开，防止推断覆盖事实。

四平台图片数、结构、语气和引导由 `backend.ai.RULES` 每次传入。平台切换会重新创建任务并生成内容；原型不能保证每次结果都具有足够差异，仍需要统一任务验收。

## 图片编排

程序不让模型创造图片 ID。先过滤型号和重复 ID，再按场景词语、场景分组与图片名称 / 描述排序，记录匹配理由；正文以空行划分内容块，匹配后记录 `after_block` 与可读位置。无场景匹配时直说需人工确认；现阶段没有声称能够理解图片像素。

## 独立核验

另一轮模型调用检查完整当前内容，重新提取 `claims`，返回 `issues / pending / claims`；空响应不能通过。程序核对来源 ID、图片型号、重复、数量，叠加风险词和动态权益检查。规则覆盖标题、导语、正文、CTA、标签与配图说明。

来源冲突在生成阶段即停止；若独立核验才发现冲突，也不保存成稿。已有作品检查发现冲突时，正式稿、草稿和海报均被阻止。编辑不直接解除冲突，需再次核验。核验是基于当前本地资料的质量检查，不代表已验证 ima 来源。

JSON 或 schema 不符最多修复一次；临时网络失败最多重试一次；不切换外部备用模型。编辑后重新核验引用当前版本，过时任务不能覆盖新稿。文本与图片均保留任务状态和取消保护。
