# 比比拉布 · 知客参赛提交指南

依据：用户提供的《华为·产业进阶赛道·赛题手册 v4》第 2、5、7、8、9 页；整理日期 2026-10-18。手册未给出具体提交入口、截止时间或说明书文件格式，均以组委会后续通知为准，不猜测。

## 直接使用

1. 双击仓库根目录的 `一键准备提交.cmd`。工具不联网、不调用模型、不上传材料；生成并打开 `output/submission/index.html`。
2. 面板提供源码 ZIP、提交字段 TXT、文件哈希清单，以及“一键复制全部字段”。全部文案使用团队名「比比拉布」。
3. 补充或更新 `docs/competition/submission.json` 中的官方提交入口、视频链接和真实复核状态，再运行一次。链接为空会显示待补齐；不能把布尔值改成 true 来代替实际验收。
4. 完成下表后，把字段粘贴到组委会正式表单，并由团队最终提交。当前没有官方表单地址，无法预先实现真实的“一键投递”。

## 手册要求与当前准备

| 要求 | 材料位置 | 当前边界 / 提交前动作 |
| --- | --- | --- |
| 初赛 GitHub 源码、README、安装和依赖 | 根目录 README、requirements、frontend/package-lock.json | 仓库链接见 submission.json；新电脑仍需自己的模型凭证和合法取得的知识包 |
| 魔搭项目、模型或应用展示页 | MODELSCOPE_COPY.md、submission.json | 展示页应与源码和说明书一致；展示页本身不是在线生成服务 |
| 作品说明书及至少一组可辨认结果 | WORK_DESCRIPTION.md、RESULT_EXCERPT.md | 已说明旧版真实文本结果及人工修订；不是 store-v3 或 ima 验收 |
| 系统提示词八模块 | backend/prompts/marketing-system.txt、PROMPT_DESIGN.md | 提示词是实际代码读取文件；当前 local_zip 必须如实标注 |
| 账号识别与指定 ima 知识库 | IMA_INTEGRATION.md | 已有两组新版 ima 通过案例；第三组是本地回退，不冒充 ima |
| 四部分输出及事实、图片、合规核验 | WORK_DESCRIPTION.md、EVALUATION.md | 本地流程已实现；模型质量仍需真实任务验证 |
| 复赛至少三组、两类场景、两个平台 | EVALUATION.md 的 A–L 任务 | 用 ima 重新运行并保存输入、输出、图源与核验 |

| 链接评审期无需额外授权 | submission.json | 退出登录后人工打开 GitHub、魔搭、说明书、视频并核对 |
| 不泄露凭证或对外传播知识库原件 | 白名单打包、.gitignore、扫描 | 源 ZIP、图片原件、数据库、聊天、管理员初始密码均不上传 |

## 文案用法

- `SUBMISSION_COPY.md`：标题、简短介绍、完整介绍、创新点、运行条件和已知限制，供表单粘贴。未获得字数限制，因此提供不同长度版本，不冒充官方字段。
- `MODELSCOPE_COPY.md`：项目展示页正文。与说明书统一说明“本地 ZIP / ima 待接入”。
- `WORK_DESCRIPTION.md`：评委入口，包含功能流程、架构、运行结果和限制。
- `RESULT_EXCERPT.md`：一组保存结果的文字节选，标记真实旧版、人工修订、不含原图、不代表新版本验收。

## 仓库与复现

公开源码不携带私有数据。现有部分后端集成测试读取特定本地知识索引（包含 10 个产品、112 张图片的历史快照），新克隆仓库没有该数据时，不能直接复现完整测试结果。不要把测试失败解释为已取得知识库权限；也不要为通过测试上传该资料。

无需私有数据的提交工具检查：

```powershell
python -m unittest scripts.test_submission
python scripts/prepare_submission.py --check
```

完整应用需按 README 创建虚拟环境、安装后端依赖、构建前端、创建管理员并导入有权使用的知识包。未配置文本模型时不会生成模拟答案。评委可查看源码、说明书与真实证据，团队另行提供具备权限的运行演示。

后续源码更新应先扫描、运行相关测试与依赖审计，再审阅 `git diff` 后推送。准备脚本不会自动执行 Git 提交、推送或创建远端资源。

## 正式提交尚需完成

初赛已有源码、文案和可辨认的真实结果，仍需填写组委会正式入口并复核链接。复赛还需补齐全部 ima 案例、同产品换场景对照和真实视频。已经建好链接或本地打包成功，不等于作品满足全部赛题要求。

本次上传使用独立的 `output/github-repository/` 发布副本，避免其他聊天同时编辑造成中间状态混入。平时继续在原工作目录开发；一键准备入口重新打包当前工作目录，不会自动更新 GitHub。再次发布前应重新测试、审阅差异并同步到发布副本。
