## 自动化验证与真实结果的边界

`tests/test_competition.py` 是离线回归，覆盖未知信息、不确定型号、场景选图、四部分导出、正文插图、来源冲突、草稿与海报绕过、标签 / 说明合规，以及修改后失效。`CompetitionEvidence.test.tsx` 覆盖详细依据窗口及插图显示。原有权限、任务、备份、版本测试继续保留。

`tests/e2e_server.py` 的模型是明确标记的夹具。其浏览器测试验证界面流程，不证明模型理解、事实真实性、ima 接口或真实生成质量。

真实调用仍需单独授权；本轮不运行下列命令。准备好后使用新的 run-id 保留历史记录：

```powershell
.\.venv\Scripts\python.exe scripts/real_acceptance.py --text --suite handbook --run-id handbook-v3-ima-01
```

该脚本准备 A / D / C / B / E 五个合成业务任务，保存任务 ID、原始作品与核验结果；失败也如实保留。G-J 等干扰任务按表手动执行并记录。`passed` 仅代表检查通过，不能自动替代两场景之间的人工差异评价。当前脚本仍使用项目当前知识提供器，只有真实接通 ima 后才可作为 ima 案例验证。
