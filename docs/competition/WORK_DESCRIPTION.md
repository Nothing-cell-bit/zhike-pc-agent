## 作品解决的问题

门店面对学生、差旅人士等不同顾客，需要把产品事实转成适合不同平台的营销图文。知客将任务理解、平台规则、型号绑定、配图、独立核验和导出串成流程；客户咨询和人工客服作为业务入口，营销任务也可单独创建。

自研 Agent 负责策略、内容组织、规则检查、版本和导出；大模型负责理解和表达。`ima_first` 模式优先调用指定共享库，失败时整体回退本地 ZIP，并记录实际来源和回退原因。后续核验与导出沿用作品来源快照；不能把本地回退结果当作 ima 图源验收。

## 功能与使用流程

1. 客服登录后进入“营销内容—新建内容”，选择完整产品型号、平台、人群、具体场景与内容目标；购买阶段和主要问题可补填，未提供的购买阶段记为待确认。
2. 必要输入不足或产品无法识别时请求补充，不按“轻薄本”等模糊描述猜唯一型号。
3. 读取型号对应的事实与限制资料。模型先检查来源是否冲突，再生成标题、导语、正文、标签、CTA 和内容策略。
4. 程序只从同型号图片中，按场景与图片描述的词语及场景分组匹配排序；保留选择理由。它是可解释的规则匹配，不代表已实现视觉识别。无匹配时标明需人工确认，不冒充理解图片画面。
5. 配图按当前正文匹配插入，图片不足和重复不能凑数。图文预览及 Markdown / HTML 使用记录的位置。
6. 独立模型重新提取当前稿事实并核验；规则额外检查绝对化词语、动态权益、图片数量、重复与型号，检查范围包含标签和配图说明。
7. 修改后新建版本并撤销通过状态，原策略标为修改前记录。来源冲突会阻止正式稿、草稿和海报输出，必须再次核验；一般待确认稿可明确标记为草稿。
8. 点击“查看创作依据”，展开场景、资料和事实点、配图说明、核验结果；日常编辑区保持简洁。复制和导出按赛题四部分格式组织。

## 四个平台的策略

| 平台 | 内容组织 | 图片 | 行动引导 |
| --- | --- | --- | --- |
| 公众号 | 标题、导语、分节展开问题、事实与限制 | 2-4 张 | 带任务清单到店体验 |
| 小红书 | 口语标题、短段落、具体场景、核对清单与标签 | 3-6 张 | 评论、咨询；不伪造亲身体验 |
| 朋友圈 | 短文案、一个核心卖点 | 1-3 张 | 私信或到店 |
| 海报 | 主副标题、最多 3 个卖点、活动说明 | 1 张主视觉 | 明确到店或咨询；未知活动不编造 |

这些是系统约束，生成质量仍需真实任务与人工复核，不能用单元测试证明所有输出均达到发布质量。

## 架构与提示词

```mermaid
flowchart LR
    A[任务输入与补充] --> B[绑定完整型号和读取证据]
    B --> C[场景判断与平台策略]
    C --> D[检查来源冲突并生成图文]
    D --> E[同型号选图与正文编排]
    E --> F[独立事实核验与合规检查]
    F --> G[人工编辑与重新核验]
    G --> H[四部分导出与版本记录]
```

- 前端：React、TypeScript、Ant Design；后端：FastAPI、SQLAlchemy、SQLite。
- 知识检索：版本化 ZIP、文件完整性校验、中文 FTS5、型号过滤、原文与图片引用；不是向量检索。
- 文本模型：服务端配置的 `qwen3.8-27b`；没有配置时显示失败，不伪造答案。
- 提示词唯一正文：[系统提示词](../../backend/prompts/marketing-system.txt)，代码在每次模型调用中实际读取，覆盖角色、场景、平台、知识库、图片、生成、核验、合规八模块。
- 每次调用还附任务指令、JSON schema、产品证据和平台规则；见 [提示词与调用说明](PROMPT_DESIGN.md)。
- 安装、依赖和启动步骤见 [项目说明](../../README.md)。
